# Телефон получателя

Для новых заказов `POST /orders` и `POST /orders/guest` требуют поле
`recipientPhone`. Используется международный формат с `+` и кодом страны.
Например, `+7 (701) 123-45-67` сохраняется как `+77011234567`.

Backend, веб и приложение используют одну версию `libphonenumber-js/max`:
проверяются код страны, длина и допустимые цифры номера. Пробелы, скобки,
точки и дефисы допустимы; текст, добавочные номера и номера без кода страны
отклоняются. Проверка формата не подтверждает владение номером и его доступность.

В `Order.recipientPhone` хранится контакт именно этого заказа. У аккаунта в
`User.phone` хранится последний использованный номер. Создание заказа и
обновление `User.phone` выполняются одной транзакцией. Повтор уже выполненной
попытки по ключу идемпотентности возвращает исходный заказ и не перезаписывает
более новый телефон аккаунта. Телефон входит в отпечаток содержимого заказа.

Для аккаунтов автоподстановка берёт номер из ответа `/auth/me`, поэтому
сохранённый номер доступен после нового входа и на другом устройстве. Для
гостей телефон сохраняется в заказе в БД, а автоподстановка на этом устройстве
использует localStorage сайта или SecureStore приложения. Чужие номера не
ищутся через публичный API, а номер гостя не переносится в другой аккаунт.
Если хранилище устройства недоступно, успешный заказ сохраняется, но номер
может потребоваться ввести снова после перезапуска клиента.

Миграция `20261027160000_add_order_recipient_phone` добавляет поля, оставляя
их пустыми у существующих пользователей и старых заказов. Новые запросы без
телефона получают 400. Перед включением требования на backend нужно выпустить
обновления веба и мобильного клиента, содержащие поле телефона: старые сборки
без этого поля не смогут оформить новый заказ. Все накопленные миграции
применяются командой `npx.cmd prisma migrate deploy` из `sushi-backend`.

Правила библиотеки: [libphonenumber-js](https://github.com/catamphetamine/libphonenumber-js#isvalid-boolean).
