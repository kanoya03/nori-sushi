# Сессия и актуальность корзины

## Восстановление входа в приложении

Отсутствие сети, таймаут и ошибки сервера не удаляют токен из SecureStore.
При запуске приложение предлагает повторить восстановление. Переход к гостю
возможен по отдельной кнопке выхода. Неверный токен удаляется при ответе 401.
Версия операции и отмена запроса защищают новый вход и выход от позднего
ответа предыдущего восстановления; записи токена в SecureStore выполняются
по очереди. На сайте сохранение токена при временных ошибках уже действовало.

Мобильный API-клиент имеет таймаут 30 секунд на запрос вместе с чтением тела
ответа. Методы принимают `signal` и `timeoutMs` последним параметром options.
При отмене снимаются слушатели и таймер. Оформление заказа отменяет ожидание
при уходе с экрана; это не отменяет заказ, который сервер уже сохранил.

## Проверка заказа

Перед первой отправкой заказа сайт и приложение запрашивают `/products`
и сверяют выбранные позиции с текущими товарами. Цена и сведения о блюде
обновляются; изменение требует ещё одного нажатия подтверждения. Количества
сохраняются. Недоступные позиции отмечаются для удаления самим покупателем.
Если каталог недоступен, новый заказ не отправляется.

Новые клиенты передают `items[].expectedUnitPrice` — цену, которую видел
покупатель, в исходных денежных единицах backend. Сервер считает заказ по
ценам из БД и сравнивает их с ожидаемыми. Изменившаяся цена или недоступная
позиция возвращает 409 с `code: CART_CHANGED`, без сохранения заказа. Клиент
обновляет корзину и просит пересмотреть её. Для старых клиентов поле цены
остаётся необязательным; проверки выполняются при его наличии.

Цены-предусловия не входят в ключ попытки и отпечаток заказа. После
неопределённого ответа уже начатая попытка повторяется с прежним ключом,
чтобы сервер мог вернуть ранее созданный заказ даже при исчезновении блюда
из каталога. Если заказа ещё нет, сервер проверяет цены перед сохранением.
Содержимое корзины, контакт, способ получения и другие данные заказа входят
в идентичность попытки. Изменение этих данных создаёт новую попытку.

Дополнительная миграция БД для этих изменений не нужна. Ранее подготовленные
миграции применяются перед публикацией обновлённого backend.

Проверки: `npm test` в backend и мобильном проекте, а в веб-проекте
`npm run test:e2e -- tests/commerce.spec.ts`. Тесты используют подменённый HTTP
и изолированную БД; реальные заказы при проверке не создаются.
